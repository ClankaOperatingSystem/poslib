#+TITLE: Formats

The byte-level formats poslib and [[https://github.com/monkeypants/pyposlib][pyposlib]] share. Both implement
this document, version 11, in lockstep; the fixtures in =fixtures/= are its
examples, and both test suites run all of them. Org interpretation is not
shared: it has one implementation, poslib's.

* Content identifiers

A file's or directory's CID is the one =ipfs add= computes under the
unixfs-v1-2025 import profile of [[https://specs.ipfs.tech/ipips/ipip-0499/][IPIP-499]]:

- CIDv1, sha2-256, written in multibase base32, lower case (=b...=).
- A file is cut into 1 MiB chunks, each a raw block. One chunk, including
  an empty file, is its own CID. More chunks form a balanced DAG of dag-pb
  UnixFS file nodes of at most 1024 links, levels built from the left.
- A directory is a dag-pb UnixFS directory node linking its entries in
  byte order of their names; each link's size is the whole DAG beneath it.
- Names are hashed as stored, in whatever Unicode normalisation.
- Hidden entries, those whose names begin with =.=, are left out.
- Symlinks and other special files are refused.
- A directory node of more than 262144 bytes, which IPFS would shard, is
  refused (=sharding-unsupported=) until sharding is implemented.

Fixtures: =fixtures/cid/=. Each gives a tree, the entry to hash, and its
CID or error. =params= overrides the chunk size and link limit, as
=--chunker= and =--max-file-links= do. kubo, run offline, is the referee.

* Canonical JSON

Ledger events and checkpoints are JSON written one way, so that equal
values are equal bytes:

- Values: objects, strings, integers and =null=.
- Object keys in the byte order of their UTF-8 encoding, which is code
  point order.
- No whitespace between tokens; one newline after the value.
- Strings in UTF-8, unescaped, except: =\"= and =\\=; =\b=, =\f=, =\n=,
  =\r= and =\t=; other characters below U+0020 as =\u00xx=, lower-case
  hex. DEL and all non-ASCII characters are written raw.
- Integers in decimal, without sign unless negative, without exponent.

Fixtures: =fixtures/json/=, each a value and its encoding.

* Archive ledgers

Each outermost =archives/= directory has a ledger. A scope keeps its
ledger and checkpoints beside its archive, in =archive-integrity/=:

- =archive-integrity/ledger/=: the ledger's events;
- =archive-integrity/checkpoints/=: checkpoints of ledger heads.

The archive itself then holds only archived material. When a scope
retires into its parent's archive, its =archive-integrity/= goes with it,
as ordinary content inside the parent's CID.

The legacy layout, read until archives are migrated, keeps the ledger
inside the archive, in =archives/.archive-integrity/=, and checkpoints in
=.archive-integrity-anchors/= beside the root. An archive with a ledger in
both places is refused (=ledger=).

** Discovery

From a root: the root itself if it is named =archives=; otherwise every
directory named =archives= beneath it, not descending into one found, nor
into any directory whose name begins with =.= or =_=. A symlinked
directory met on the way is refused.

** Inventory

Every file beneath the archive, except a legacy ledger directory at its
top, hidden and underscored files included. Each is a regular file with
one link, else refused; a symlinked directory is refused. Each entry is:

- =sha256=: lower-case hex of its bytes;
- =size=: its length;
- =mode=: its permission bits, the low twelve, with every write bit
  cleared.

Paths are relative, =/=-separated, with no empty, =.= or =..= component.
An archive not yet made has an empty inventory.

** Collections

A collection is a directory whose =README.org= contains the line
=#+COLLECTION: t=: those exact bytes, between line feeds or the file's
ends; or a capsule, a directory whose =manifest.json= is an object with
=schema_version= 1, =entries= and =entrypoint=. The event that seals it
lists its path. A capsule is a frozen snapshot with its own verification,
kept byte for byte: its links are left as written, broken ones included,
and no =README.org= is added to it.

** Events

The ledger is a sequence of files named =NNNNNNNN-HASH.json=: an
eight-digit number counting from 1 without gaps, and the SHA-256 of the
file's bytes. Each holds one event in canonical JSON, of schema 1 or 2.
Once an event has schema 2, every later one does.

Schema 1:

- =schema=: 1.
- =previous=: the hash of the preceding event, =null= for the first.
- =add=: the entries enrolled, by path. A path is enrolled once; no path
  lies in a legacy ledger directory; no mode has a write bit.
- =ledger_id=: a UUID in canonical lower-case form, the same in every event
  that has one. Once present it stays; events before the first that has
  one may lack it.

Schema 2 has the same, with =ledger_id= required, and:

- each entry in =add= also has =cid=, the file's CID;
- =item=: the path of the item the event sealed, a file or a directory;
  every path in =add= and =collections= is the item or lies within it;
- =root=: the archive's CID after this event;
- =collections=: the paths of the collections this event seals, sorted,
  each once; possibly none.

A conversion event, once in a ledger that holds legacy entries (those
without =cid=), migrates them all: =schema= 2, =kind= =conversion=,
=previous=, =ledger_id=, and:

- =remove=: legacy paths no longer enrolled, sorted;
- =rename=: each legacy path renamed, by its old path, to its new;
- =convert=: every legacy entry left, by its path after renaming, as a
  schema 2 entry with =from=, the SHA-256 it was enrolled with;
- =add=: files enrolled for the first time, as schema 2 entries;
- =collections=: every collection in the archive, sorted;
- =root=: the archive's CID after it.

The head is the hash of the last event; the recorded root is the last
event's =root=, if it is of schema 2. An empty ledger directory is
refused. Refusals are named: =ledger= (the ledger is not a directory, or
there are two), =sequence= (name, number or hash), =chain= (keys, schema or
=previous=, or a conversion where there is nothing legacy to convert),
=identity=, =entry= (an entry, =item=, =root= or =collections=, or a
conversion that leaves a legacy entry unaccounted for, names a wrong
original or adds over an entry) and
=empty=; =link= refuses a symlink or a second hard link anywhere.

** Checkpoints

A checkpoint records ledger heads, to detect a vanished archive or a
truncated ledger. It lives in =archive-integrity/checkpoints/= beside the
root it covers, or in the legacy =.archive-integrity-anchors/=, named by
the SHA-256 of its bytes, holding in canonical JSON:

- =schema=: 1;
- =heads=: sorted event hashes;
- =coverage=: =archive= for a root named =archives=, else =tree=.

Every head a checkpoint names must be the hash of some event file of the
archives found, or of a ledger within them, legacy or current, as
retired scopes carry; otherwise the check refuses (=anchor=).

** Check

For each archive found, in path order compared component by component,
a report:

- =archive=: its path; =head=, =events= and =files=;
- =missing=, =changed=, =new=: enrolled paths absent, enrolled paths
  whose entry differs, and unenrolled paths, each sorted. A schema 2
  entry differs if the file's CID does, too;
- =writable=: files and ledger events with any write bit, sorted, ledger
  events by their path from the archive (=../archive-integrity/ledger/...=);
- =checkpoint_writable=: writable checkpoint files, in the first report
  only;
- =root=: the archive's CID now, or =null= if IPFS would shard a
  directory in it; =recorded_root=: the recorded root, or =null=;
- =hidden=: files with a hidden component, other than within legacy
  ledger and checkpoint directories, sorted; sealing refuses them;
- =undeclared=: collections the ledger lists whose =README.org= no longer
  declares them, sorted.

A root differing from the recorded root shows a change since sealing
that no file shows, such as an added directory.

Fixtures: =fixtures/ledger/=: inventories with their first event,
ledgers valid and refused, in both layouts and schemas, and reports.

* Sealing

Everything enters an archive by sealing, in two steps: a plan, which is
reviewed, then its application. The reviewer names the plan by the
SHA-256 of its canonical JSON; application refuses any other.

** Plans

=seal SOURCE DESTINATION= plans to move SOURCE, a file or directory
outside any archive, to DESTINATION, a path that does not yet exist inside
an outermost =archives/=, which itself need not exist yet. =write-new
DESTINATION= first stages new bytes in =_seal/= beside the archive, in a
file with DESTINATION's extension, then plans the same way, reading their
links as written from DESTINATION; if planning fails, the staged file is
removed, and =_seal/= with it if left empty. A plan holds, in
canonical JSON:

- =schema=: 2; =operation=: =seal=;
- =source=, =destination=, =archive=, =ledger=: absolute paths, the archive
  and ledger folder resolved; the ledger folder is the archive's, or for
  an archive without one, =archive-integrity/ledger/= beside it;
- =number= and =previous=: the event to be written and the head it
  follows, =null= for none;
- =ledger_id=: the ledger's, else one supplied, else a random version 4
  UUID;
- =add=: the item's files by path within the archive, each a schema 2
  entry of its bytes once its links are rewritten: =cid=, =mode= less write
  bits, =sha256=, =size=;
- =links=: every path link in the item, sorted by file then offset: =file=,
  =offset= in bytes, =from= and =to= the link's text before and after, and
  =kind=, =cid=, =rumour=, =internal= or =broken=;
- =originals=: the SHA-256 of each file whose links change, as it is;
- =rumours=: the rumour records to seal first, sorted by destination:
  =destination= within the archive, =text= and =cid=;
- =collections=: the directories in the item, itself included, whose
  =README.org= declares them, sorted;
- =inventory_sha256=: the SHA-256 of the archive's inventory, in
  canonical JSON, as planned.

Planning refuses: =source= (missing, or already archived), =destination=
(not in an archive, existing, or unsafe), =sealed= (the destination lies
within an item or collection already sealed: a sealed item never grows), =hidden= (a hidden file in the
item, or a hidden destination), =link= (a symlink or second hard link in
the item), =differs= (enrolled evidence in the archive is missing or
changed), and for links, =unsealed=, =unresolved= and =loop=, below.
Hidden or unenrolled files already elsewhere in the archive do not stop a
seal; the check reports them.

** Links

Links are sought in the item's files, other than a capsule's, named
=*.org=, as Org parses them:
links of type =file=, in any form, their search options kept; and named
=*.md=, as markdown-mode finds them: inline links and images, and
reference definitions, outside code, their fragments kept, their paths
URL-decoded. A Markdown URL with a scheme is not a path.

Each link's path is taken from the file where it was written, before the
move, and resolves:

- within the item: in a collection holding both files, the link stays as
  written (=internal=); to another file of the item, it cites that file's
  CID, taken once that file's own links are rewritten (=cid=); links among
  an item's files that form a loop are refused (=loop=); anything else
  within the item is refused (=unresolved=);
- to a path in the archive of the item's scope, or of a scope within it:
  =ipfs://= and the CID of the sealed item holding it, else of the
  collection holding it, else of the enrolled file itself, then =/= and
  the path within it if it is not the whole (=cid=); a path never sealed
  is refused (=unsealed=);
- to anything else that exists, canon, another scope, or a container's
  archive, since a scope does not depend on its container: a rumour
  record, sealed first as an item of its own, whose CID the link cites
  (=rumour=);
- to nothing: kept, annotated as broken (=broken=). The annotation
  replaces the whole link: in Org the link's type becomes =broken:=, as
  =[[broken:PATH][TEXT]]=; in Markdown the link becomes =TEXT [broken
  link: PATH]=.

A resolved link's target is replaced whole: in Org the raw link, as
=ipfs://CID/PATH::SEARCH=; in Markdown the URL, as =ipfs://CID/PATH#FRAGMENT=.

A rumour lies at =rumours/DATE-HASH.org= in the archive, HASH the first 12
hex digits of the SHA-256 of its text, DATE the plan's; one rumour serves
every link to its target from the item, and rumours of one target that
differ in word differ in name. Its text is:

#+begin_example
,#+TITLE: Rumour of PATH
,#+DATE: DATE

On DATE, sealing =ITEM= found a link to =PATH=, outside the archive. It was then DESCRIPTION.
#+end_example

DESCRIPTION is =outside the garden, and was not read= for a target beyond
the garden's repository, which is never read; else =a directory=, or =a
file of N bytes, SHA-256 =HEX== with
=, titled "TITLE"= if the file has an Org =#+TITLE= or a Markdown =#=
heading. A rumour already sealed, word for word, is cited, not sealed
again; one differing at its destination is refused (=destination=).

Planning an item that holds Org or Markdown files is poslib's, since Org
interpretation is; pyposlib refuses to plan it (=interpretation=), and
applies any plan.

** Application

1. The plan's hash must be the one reviewed, else =plan=.
2. The events since the plan's =previous= must seal a prefix of its
   rumours, then its item, in order, else =plan=; before any, the archive's
   inventory must be as planned.
3. Each rumour not yet sealed is published at its destination and sealed:
   an event whose =item= is the rumour and whose =add= is its entry.
4. Unless the item has moved already, each file in =originals= is
   rewritten where it lies, its links replaced at their offsets, unless it
   has been already; the item's entries must then be as planned, else
   =plan=; then the item moves to its destination in one rename.
5. The item's entries at the destination must be as planned, else =plan=.
6. Unless sealed already, its event, of schema 2, is written: =previous=,
   the ledger's head; =ledger_id=, =add= and =collections= from the plan;
   =item=, the destination's path within the archive; and =root=, the
   archive's CID now.
7. Write bits are removed from the item's files and the rumours; events,
   like every ledger and checkpoint file, have mode =0444=.
8. A checkpoint of the archive's head, of coverage =archive=, is written
   beside the archive: in =archive-integrity/checkpoints/= if
   =archive-integrity/= exists there, else in the legacy folder.

Applying a plan again after an interruption finishes it, and after
completion changes nothing.

A program that seals or writes records itself, with no one to review each
plan, uses =seal SOURCE DESTINATION --apply= or =write-new DESTINATION
--apply=: it plans, applies that plan at once
under its own hash, and prints =plan=, =hash=, =event= and =root=. The
plan and its refusals are those of the two-step form.

Fixtures: =fixtures/ledger/seal-*=: a tree, a source and destination, a
date for rumours, and the plan, the last event and the report after it,
paths relative to the tree; or the refusal.

* Migration

The one sanctioned rewrite of archived bytes: an archive whose ledger
holds legacy entries is rebuilt, in content identity, and its ledger
closed by a conversion event. Migration is poslib's, as planning links
is.

A plan, reviewed and applied as a seal's is, describes the rebuilt
archive:

- =discard= and =remove=: Finder's =.DS_Store=, unenrolled and enrolled;
  =remove= also holds enrolled paths missing already;
- =renames=: in order, a legacy ledger folder within the archive to
  =archive-integrity/ledger/= beside its archive, a legacy checkpoint
  folder to =archive-integrity/checkpoints/=, and any other hidden entry
  to its name prefixed =dot=, keeping its bytes;
- =collections=: the receipts (with =manifest.json= and =source/=),
  capsules (in =capsules/=), runs (in =trials/=, =studies/= or
  =pipeline-trials/=), retired scopes (holding =archives/=) and capsules,
  none within another, less those the reviewer excludes and with those
  the reviewer includes, which their shape does not show;
  =declarations=: each but a capsule declared in its =README.org=, the
  line added after its leading keywords, or a new =README.org= made,
  naming the collection's entrance;
- =rumours=: at =rumours/DATE-HASH.org=, as for sealing, the text saying
  that migrating the archive found links to the path;
- =links=: every link, as for sealing, from where it was written, with its
  resolution; a scope within this one must be migrated first, and a
  container's archive is cited by rumour; a link to a path gone from the
  archive whose counterpart at the same relative path from the scope
  exists means the counterpart: a withdrawn record's in canon, cited by
  rumour, or a record's archived since the link was written, cited by
  CID. Each link has its edit: =cid=, =internal=, =rumour=, =broken=, annotated, or =later=, a
  link from an earlier item to a later one where items' links loop,
  annotated =[[later:PATH][TEXT]]= in Org and =TEXT [later record: PATH]= in
  Markdown; an item's date is one its path begins with, else its first
  commit's;
- =canon=: each canon file under the plan's root with links to a path the
  migration moves, its SHA-256 and the edits repairing them;
- =inventory_sha256= and =final_inventory_sha256=: the archive before and
  after; =event=: the conversion event's name and text.

Applying the plan rebuilds the archive in =_migrate/= beside it, refusing
any difference from the plan, keeps the archive as it was there, swaps
the rebuilt archive in, moves the ledger and checkpoints beside it,
writes the conversion event, removes write bits, repairs canon and
checkpoints the head. Applied again, it finds its work done.

* Fixture trees

A fixture's =tree= lists entries by =path=, one of:

- =text=: a file of that string's UTF-8 bytes;
- =repeat=: =[BYTE, COUNT]=, a file of COUNT copies of BYTE;
- =pattern=: =N=, a file of the bytes =i mod 251= for =i= below N;
- =series=: =N= with =text=, N files, =path= holding =%04d= for the index;
- =directory=: true, an empty directory;
- =symlink=: a target; =hardlink=: another entry's path.

=mode= sets a file's permission bits, default =0644=.
